# AI Tool Usage Note

Built with **Claude Code** (Anthropic's CLI agent, this session) as the primary coding tool, used end-to-end:

- **Planning**: the locked-scope spec (`parcelpilot_spec.md`) was produced in an earlier planning session and treated as the source of truth for this build — every architecture decision below traces back to a line in that file rather than being re-decided ad hoc.
- **Data inspection (Stage 0)**: a dispatched research pass read every sheet of the xlsx and extracted full text from all 6 PDFs before any code was written, to get exact column names, dollar/rupee amounts, hour thresholds, and quoted contract clauses rather than guessing them. That inspection report is what the code (fee/credit logic left to the model + policy text, not hardcoded numbers) and the trap-test questions are built from.
- **Code generation**: all backend and frontend modules were generated by Claude Code directly, module by module, each with a stated purpose and explicit `ponytail:`-style rationale for simplifications (e.g. why pandas instead of SQLite, why TF-IDF instead of a vector DB).
- **What I owned personally rather than accepting as-is**: the access-control design (account_id bound server-side, never model-controlled) and the confirmation-gate design (propose vs. execute as two separate, separately-reachable functions) are the correctness-critical parts of this system — I reviewed and reasoned through both explicitly rather than trusting generated code to get them right by default, and the test suite (`test_access_control.py`, `test_confirmation_flow.py`) exists specifically to prove those two properties rather than assert them.
- **Every generated change was reviewed before being treated as final** — nothing here was accepted unread.
